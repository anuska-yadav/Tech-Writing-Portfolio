# GitHub Collaboration and Contribution Workflow

## 1. Collaboration on GitHub

GitHub provides features that allow multiple contributors to work on the same project.

The Git lecture introduces the following collaboration features:

- Forking
- Issues
- Pull Requests
- Code Reviews
- Projects

## 2. Forking a Repository

A fork is a copy of another user's repository under your own GitHub account.

It allows you to work independently on a copy of the original repository.

Forking is useful when you want to contribute to a project without directly modifying its original repository.

## 3. Issues

GitHub Issues are used to discuss and track:

- Bugs.
- Tasks.
- Improvements.
- Project-related discussions.

They help contributors organize and follow project work.

## 4. Pull Requests

A Pull Request (PR) is used to propose changes from one branch to another.

It allows other contributors to review the proposed changes before they are merged.

### Pull Request Workflow

1. Create a branch for the required changes.
2. Make changes in that branch.
3. Stage and commit the changes.
4. Push the branch to GitHub.
5. Open a Pull Request.
6. Allow collaborators to review the changes.
7. Merge the Pull Request when approved.

## 5. Code Reviews

Code review is the process of examining proposed changes before merging them.

It allows collaborators to:

- Review the changes.
- Identify possible problems.
- Provide feedback.
- Discuss improvements.

## 6. Fork vs Clone

Forking and cloning both create copies of a repository, but they work in different places.

| Fork | Clone |
|---|---|
| Creates a copy on GitHub. | Creates a local copy on your computer. |
| Used when contributing to another repository. | Used to work with a repository locally. |

## 7. Collaborative GitHub Workflow

A typical contribution process is:

1. Fork the original repository when required.
2. Clone the repository to your computer.
3. Create a separate branch.
4. Make changes and create commits.
5. Push the branch to GitHub.
6. Open a Pull Request.
7. Participate in code review.
8. Merge the approved changes.

## 8. Key Takeaway

GitHub supports collaborative development through forks, issues, pull requests and code reviews. These features help contributors discuss, propose, review and integrate project changes.
